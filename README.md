# 2way 교차로 차량 분석 통합 시스템

YOLO 기반 영상 분석기로 교차로 출입 차량을 추적·집계하고, 로컬 웹 대시보드에서 분석 실행과 진행 상태 및 결과를 확인하는 Windows용 통합 프로젝트입니다. 영상과 분석 결과는 외부 서버로 전송하지 않고 랩실 컴퓨터에서 처리합니다.

## 주요 기능

- 2방향 도로(통과선 1개)부터 T자·Y자·십자·오거리·회전교차로(접근로마다 통과선 1개)까지 같은 방식으로 분석
- 통과선(접근로)별 `유입`·`유출`, 출발→도착(OD) 행렬, 직진·좌회전·우회전·유턴 15분 집계
- 통과선 방향과 무관한 법선 기반 판정: 가로·세로·대각선 통과선 모두 동일하게 동작
- 가림과 추적 ID 변경을 줄이기 위한 BoT-SORT + ReID 및 ID 조각 재연결
- 야간·빠른 차량을 고려한 적응형 통과 확인
- 작은 오검출을 제외하는 최소 바운딩박스 조건
- ROI 실제 크롭과 프레임 선행 디코딩을 통한 처리 시간 단축
- 영상별 15분 집계 CSV와 선택 가능한 차량별 상세 CSV 저장
- 브라우저 대시보드에서 시험 분석, 전체 분석, 중지, 진행 상태 및 결과 확인
- 분석기와 대시보드를 독립 프로세스로 실행해 브라우저를 닫아도 분석 지속

## 시스템 구조

```text
통합실행.bat
├─ integrated_launcher.py
│  ├─ local_agent.py              로컬 분석 API (127.0.0.1:8765)
│  │  └─ two_way_counter.py       실제 영상 분석·집계
│  └─ dashboard                   로컬 웹 대시보드 (127.0.0.1:3000)
├─ analysis_status.json           분석 진행 상태
├─ 영상별 CSV                     완료된 영상 단위 결과
└─ logs                           분석기·대시보드 오류 로그
```

대시보드는 같은 컴퓨터의 신뢰된 로컬 주소에서 분석 API에 자동 연결됩니다. 주소나 토큰을 복사할 필요가 없습니다.

## 처음 설치

1. 프로젝트 폴더에서 `설치.bat`을 더블클릭합니다.
2. Python 가상환경, 분석 패키지, 휴대용 Node.js 및 대시보드 패키지가 설치됩니다.
3. 설치 마지막에 대시보드 프로덕션 빌드가 생성됩니다.
4. 설치가 끝나면 `통합실행.bat`을 실행합니다.

YOLO 모델 파일은 첫 분석 시 자동으로 내려받을 수 있습니다. 기본 모델은 `yolo26l.pt`입니다.

## 통합 실행과 종료

- `통합실행.bat`: 분석 API와 대시보드를 숨겨진 독립 프로세스로 시작하고 브라우저를 엽니다.
- `통합종료.bat`: 통합 실행기가 시작한 분석 API와 대시보드를 함께 종료합니다.
- 대시보드 주소: `http://127.0.0.1:3000`
- 분석 API 주소: `http://127.0.0.1:8765`

브라우저 또는 Codex 대화를 닫아도 실행 중인 분석은 계속됩니다. 컴퓨터를 종료하거나 `통합종료.bat`을 실행하면 중단됩니다.

## 분석 전 설정

1. 대시보드 또는 `실행.bat`에서 영상 폴더와 결과 폴더를 선택합니다.
2. `실행.bat` 화면에서 **교차로 형태**(2방향 도로, T자·Y자, 십자, 오거리, 회전교차로, 직접 지정)를 고르고, 필요하면 **접근로 이름**을 쉼표로 적습니다. 예: `북,동,남,서` (비우면 A, B, C …)
3. `1. 영역·통과선 설정`을 누릅니다.
4. 1단계: 차량이 다니는 영역을 왼쪽 클릭으로 3점 이상 지정하고 `Enter`를 누릅니다. 영역은 **모든 통과선 바깥쪽 도로를 조금씩 포함**해야 합니다.
5. 2단계: 접근로마다 도로를 가로지르는 선의 양 끝을 차례로 클릭합니다(2번 클릭 = 통과선 1개). 2방향 도로는 1개, 십자 교차로는 4개를 그립니다.
6. 화살표가 `유입`(교차로 안쪽) 방향입니다. 여러 개면 교차로 중심 쪽으로 자동 설정되고, 방금 그린 선의 화살표가 반대면 `F`를 누릅니다.
7. `Enter`를 눌러 `config.json`에 저장하고 `영역설정_미리보기.jpg`를 확인합니다.
8. 5분 시험 분석을 실행해 사람이 센 값과 비교합니다. 결과 폴더의 `분석요약.txt`에 합계와 점검 항목이 한눈에 정리됩니다.
9. 결과가 맞으면 전체 분석을 실행합니다.

설정 창에서 `Z` 또는 `Backspace`는 되돌리기, `R`은 현재 단계 초기화, `Esc`는 취소입니다. 통과선이 1개일 때는 화면의 `유입/유출 방향 바꾸기`로도 방향을 뒤집을 수 있습니다.

### 통과선 그리기 요령

- 통과선은 접근로의 **모든 차로를 가로지르도록** 정지선 부근에 긋습니다. 교차로 내부 깊숙이 그리면 회전 차량이 다른 선과 엉킬 수 있습니다.
- 통과선끼리 겹치거나 맞닿지 않게 합니다. 판정은 선분(유한 구간) 기준이므로 연장선만 지나는 차량은 세지 않습니다.
- 회전교차로는 진출입로마다 통과선을 하나씩 긋습니다. 회전 방향은 첫 번째 출구 = 우회전 순으로 분류됩니다.
- 회전 이름이 실제와 다르면 `config.json`의 `movement_labels`에 `{"A→C": "직진"}`처럼 직접 지정할 수 있습니다(코드 또는 접근로 이름 사용).

## 판정 기준

- 차량 박스의 하단 중앙점이 통과선의 한쪽에서 반대쪽으로 확실히 넘어간 경우만 집계합니다. 실제로 넘어간 지점이 유한한 통과선 위여야 합니다.
- 바깥→안쪽(화살표 방향) 통과는 `유입`, 안쪽→바깥 통과는 `유출`입니다. 통과선 1개(2방향 도로)의 기본값은 기존과 같이 오른쪽→왼쪽이 `유입`입니다.
- 통과선이 1개면 동일한 추적 ID를 영상 하나에서 한 번만 집계합니다(기존 방식).
- 통과선이 2개 이상이면 ID 하나당 `유입` 1회와 `유출` 1회를 집계하고, 두 통과선을 이어 출발→도착 이동을 만듭니다.
  - 진입만 보이고 영상에서 사라진 차량은 `도착 미확인`, 교차로 안에서 처음 잡혀 나간 차량은 `출발 미확인`으로 따로 셉니다.
  - 같은 통과선으로 다시 나가는 유턴은 교차로 안쪽으로 충분히(기본 60px) 들어온 경우만 인정해 정지선 부근 박스 흔들림을 유턴으로 오인하지 않습니다.
- 회전 방향은 십자(4갈래)에서는 교차로 중심 기준 접근로 순서로, 그 밖의 형태에서는 통과선 방향의 각도 차이(±45° 이내 직진)로 정합니다.
- 차종은 추적 기간 동안 신뢰도 가중 다수결로 정해 프레임마다 흔들리지 않게 합니다. 차종은 집계 판정에는 쓰지 않습니다.
- 앞차에 아래쪽이 가려진 박스(아래 변의 50% 이상, `occluded_bottom_ratio`)는 바닥점이 앞차 경계로 튀어 오집계를 만들므로 그 프레임만 판정에서 뺍니다. 다시 보이면 이어서 판정합니다.
- 작은 노이즈 박스는 폭 35px, 높이 35px, 면적 2,000px²의 기본 최소 조건으로 제외합니다.
- 빠른 차량은 통과선 수직 속도가 15px/프레임 이상이면 통과 후 2프레임으로 확인합니다.
- px 단위 기준값은 기준 카메라(1280×960, 높이 960px) 기준이며 `pixel_scale: "auto"`가 영상 높이에 맞춰 자동 조정합니다. 해상도와 관계없이 그대로 쓰려면 `1.0`으로 둡니다.

최소 크기와 방향을 비롯한 세부 값은 `config.json`에서 조정할 수 있습니다.

## 추적과 가림 복원

기본 추적기는 `botsort_reid.yaml`의 BoT-SORT + ReID 설정입니다. 차량이 서로 가려지면 잃어버린 트랙을 일정 시간 유지하고 외형 정보를 이용해 다시 연결합니다. 추적 ID가 바뀐 경우에도 이동 방향, 통과선까지의 거리, 예상 위치를 비교해 통과선 근처의 ID 조각을 한 번 더 연결합니다. 교차로 모드에서는 진입 후 아직 나가지 않은 차량이 교차로 안에서 가려진 경우에도 이어 붙여 출발→도착 기록이 끊기지 않게 합니다.

재연결이 발생하면 분석 로그에 다음 형식으로 표시됩니다.

```text
가림 ID 연결: 이전ID → 새ID
```

## 결과 파일

전체 분석 결과는 기본적으로 `results`, 5분 시험 결과는 `test_results`에 저장됩니다.

- `{영상명}_15분_유입유출_집계.csv`: 영상별 96개 시간 구간의 유입·유출·합계
- `{영상명}_차량별_통과기록.csv`: 실제 시각, 방향, 차종, 추적 ID, 신뢰도, 원본 영상, 통과선
- `15분_유입유출_집계.csv`: 전체 입력 영상의 통합 집계(교차로는 모든 통과선 합계)
- `15분_접근로별_집계.csv`: 통과선이 2개 이상일 때 접근로별 유입·유출과 합계 행
- `15분_방향별_집계.csv`: 출발→도착(회전) 쌍별 대수. 시간은 진입 시각 기준
- `15분_차종별_집계.csv`: 승용차·오토바이·버스·트럭별 유입·유출과 합계 행
- `OD_행렬.csv`: 전체 시간의 출발(행)×도착(열) 행렬과 미확인 행·열
- `차량별_이동경로.csv`: 차량마다 진입·진출 시각, 출발·도착, 회전, 상태, 차종
- `분석요약.txt`: 합계, 통과선별 수량, 상위 이동, 처리 속도, 점검이 필요한 항목을 몇 줄로 요약
- `차량별_통과기록.csv`: 전체 입력 영상의 통합 상세 기록
- `event_images`: 차량이 통과한 순간의 검수 이미지
- `검수_*.mp4`: 검수 영상 저장을 선택했을 때 생성되는 표시 영상
- `analysis_status.json`: 실행 상태, 진행률, 현재 영상, 오류 내용
- `analysis.log`, `analysis_error.log`: 일반 로그와 오류 로그

상세 CSV 저장을 끄면 수량 집계 CSV만 생성합니다. 각 영상이 끝날 때마다 해당 영상 CSV가 즉시 저장되므로 장시간 분석 중에도 완료된 결과를 확인할 수 있습니다.

## 영상 시간 환산

입력 영상은 3배속 영상이므로 영상 5분이 실제 15분입니다. 파일명의 시작 시간과 영상 재생 시간을 이용해 실제 시간대를 계산합니다.

## 교차로 설정 예시

`실행.bat`의 설정 창이 아래 값을 자동으로 저장합니다. 직접 고칠 때 참고하세요.

```json
{
  "intersection_type": "4way",
  "roi_polygon": [[150, 150], [850, 150], [850, 850], [150, 850]],
  "gates": [
    {"code": "A", "name": "북", "line": [[420, 300], [580, 300]], "inside_side": 1},
    {"code": "B", "name": "동", "line": [[700, 420], [700, 580]], "inside_side": 1},
    {"code": "C", "name": "남", "line": [[420, 700], [580, 700]], "inside_side": -1},
    {"code": "D", "name": "서", "line": [[300, 420], [300, 580]], "inside_side": -1}
  ],
  "movement_labels": {}
}
```

- `gates`가 비어 있으면 기존 `counting_line`과 `increasing_x_direction`으로 통과선 1개를 만듭니다. 기존 설정 파일은 그대로 동작합니다.
- `inside_side`는 교차로 안쪽 방향(1 또는 -1)입니다. 생략하면 교차로 중심 쪽으로 자동 계산합니다.
- `center_point`([x, y])로 회전 판정에 쓰는 교차로 중심을 직접 지정할 수 있습니다.
- `count_mode`: `auto`(기본, 통과선 1개면 ID당 한 번·여러 개면 출발→도착), `once`, `trip`.

## 기본 성능 설정

- 모델: `yolo26l.pt`
- 분석 장치: NVIDIA GPU `0` 우선, 초기화 실패 시 CPU
- 반정밀도(FP16): GPU에서 기본 사용(`half_precision`). 오류가 나면 자동으로 FP32로 전환
- 화면 배율: `pixel_scale: "auto"` (높이 960px = 1.0)
- 추적기: `botsort_reid.yaml`
- 입력 크기: 960px
- ROI 실제 크롭: 사용, 주변 여백 64px
- 프레임 선행 버퍼: 8프레임
- 검수 영상: 640px, 약 10fps

실제 집계는 원본 프레임을 사용하며, 검수 영상만 저장 공간을 줄여 생성합니다. 장시간 분석 중에는 전원을 연결하고 Windows 절전 모드를 꺼 두세요.

## 주요 파일

- `intersection_counter.py`: 통과선(게이트) 판정, ID 조각 연결, 출발→도착·회전 분류 엔진
- `two_way_counter.py`: 영상 처리, 추적 실행, CSV·요약·검수 결과 생성
- `run_analysis.py`: 배치 파일에서 사용하는 독립 분석 실행 진입점
- `local_agent.py`: 대시보드 요청을 받아 분석 작업을 관리하는 로컬 HTTP API
- `integrated_launcher.py`: 분석 API와 대시보드를 함께 시작·종료
- `app.py`: 기존 데스크톱 GUI
- `calibrate.py`: ROI와 통과선(여러 개) 설정 도구
- `dashboard/`: Next.js 대시보드 소스
- `config.example.json`: 설정 예시
- `botsort_reid.yaml`: BoT-SORT + ReID 추적 설정

## 문제 해결

### `node`, `npm` 또는 Python을 찾지 못하는 경우

`설치.bat`을 다시 실행합니다. 프로젝트는 시스템 Node.js 대신 `.runtime/node`의 휴대용 Node.js를 사용합니다.

### 통합 실행 시 이미 실행 중이라고 나오는 경우

`통합종료.bat`을 한 번 실행한 뒤 `통합실행.bat`을 다시 실행합니다.

### 대시보드가 열리지 않는 경우

`logs/dashboard.log`와 `logs/local_agent.log`의 마지막 내용을 확인합니다. 포트 3000 또는 8765를 다른 프로그램이 사용하고 있지 않은지도 확인합니다.

### 분석이 느린 경우

`config.json`에서 GPU 장치가 `0`, ROI 실제 크롭과 프레임 선행 버퍼가 활성화되어 있는지 확인합니다. 정확도 검증 없이 모델 크기나 입력 해상도를 낮추지 않는 것이 좋습니다.
